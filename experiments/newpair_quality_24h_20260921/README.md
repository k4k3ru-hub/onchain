**NewPairの24時間コホートと、Token・LP保護条件の検証（2026-09-21）**

指定した4 Venueで、同じ24時間に作成されたPoolを3,232件取得した。今回確認できた構造条件の合格は7件、条件未達は1,320件、未確定は1,905件だった。7件は今回の解析で確認できた下限であり、市場の合格総数や通常の1日当たり供給数ではない。

また、確認済み7件の対価側ETH元本は、評価時点で約0.005〜25.36 USDだった。LP保護とTokenの構造が条件を満たしていても、既存の売却原資が十分とは限らない。今回の結果だけで「参入に適したPoolが1日7件ある」とは判断できない。

**合意済みの判定基準**

1. Tokenに税・特殊な売買制限・それらを追加／変更する権限がないことを、実行コードと公開ソースから確認する。`onchain/go/evm/token_definitions.go` のChain/Networkとアドレスで定義された対価Tokenは、合意済みの信頼対象として扱う。
2. Pool全体の正の元本に対応する全LP持分が100%保護されていることを確認する。未確認の持分を分母から除外しない。
3. 管理者による解除・迂回・移行を通じた保護変更の経路も確認する。現在のロック時刻だけでは合格にしない。
4. 期限付きは残存1時間・24時間・7日を比較する。今回は確認できた合格がすべて永久保管だった。
5. 既存NewPairの基本条件に合わせ、作成後のSwap観測、元本の存在、Token metadata、参照価格による1,000 USD以上の流動性評価も確認する。これは実際のMarketHub掲載状態を復元した結果ではない。

独自の最低対価元本やDEX手数料上限は今回の合格条件に追加していない。売却原資は別に報告した。Token税0とDEX Swap手数料0は異なる。

**確認できた永久保管の実装**

Poolの `ModifyLiquidity` からPositionManagerとNFT IDを取得し、NFT所有者として `0xcd1680d26922fcd9cabfbb8a56ba40c333fd842a` を発見した。名前で事前登録したlockerを検索する方式ではない。

[公開されたLaunchLockerのソースとABI](https://sourcify.dev/server/v2/contract/8453/0xcd1680d26922fcd9cabfbb8a56ba40c333fd842a?fields=all) と、固定ブロックの実行コードを照合した。この実装は直接デプロイされ、owner・upgrade・NFTの移転／承認／元本減少を公開する経路を持たず、手数料回収時のliquidity減少量は0に固定される。実際のPositionManager bindingとNFT承認ゼロも確認した。全26 Poolのうち、全持分の履歴・現在値を照合できた9 Poolで100%永久保管を確認した。残り17 Poolは履歴欠落のため全体を確定していない。

9 Poolのうち7 Poolはnative ETHとの組み合わせで、もう片方は[LaunchTokenの公開ソース](https://sourcify.dev/server/v2/contract/8453/0x6eede15fb4c8001fdadad730c5d97b47f3185da6?fields=all)と実行コードが一致した。compiler-declared immutable領域だけを区別し、その他の実行コードは完全一致を要求した。固定供給の標準ERC-20/Permitであり、公開mint、owner、売買制限・税設定、upgradeの追加経路がないことをソースで確認した。残り2 Poolの対価Tokenは定義済み信頼Tokenではなく、Token条件とUSD参照を未確定にした。

ソース提供者が公開する検証結果・コンパイラ出力と実行コードを使った確認であり、この追加検証ではSolidityの独立再コンパイルや形式検証まではしていない。確認結果は当該実装と固定時点の状態に限定する。未知の脆弱性、発行主体の真正性、保有集中度、価格操作、将来の需要を保証する判定ではない。

ほかにClanker系のNFT保管先、Zora/Doppler系のHook・保管先、移行権限管理先も公開ソースと比較したが、全Token・外部依存まで含む閉じた検証を完了できていないため合格には含めていない。例えばClanker系では276 PoolのNFT保管先が共通だったが、参考Tokenのソースが未検証であり、この276件を一括で安全とは扱っていない。UNCXのAPI、レーティング、専用adapterは使用していない。

**欠落・稼働状況・観測の限界**

- 作成ログの範囲走査には取得失敗による欠落なし。V4のSwap/ModifyLiquidity履歴では51,565,696〜51,567,695、51,573,696〜51,575,695がHTTP 500。各範囲は初回と2/4/8秒バックオフの3再試行で失敗し、その後は再取得せず欠落を保持した。
- 429は新規実行全体で60応答。取得に失敗した値を成功や0として補完していない。中断後の再開でも成功キャッシュを再利用し、3再試行を使い切った範囲は再試行していない。
- AgentからGatewayへListを実行した時点（11:56:59〜11:57:00 UTC）は掲載0件。対象BaseのV3/V4/現行Slipstreamは `recovering / rpc_or_storage_unavailable` だった。これを市場に候補がない根拠としていない。Cetus coverageもこのAgent応答にはなかった。
- 評価対象は「この24時間に作られ、終点時点で条件を満たすと確認できたPool」。24時間の途中で一度だけ条件を満たして消えたものの数や、初回掲載時の合格数は再構成していない。
- 1期間だけでは曜日差や日次変動を測れない。安定した「1日何件」の推定には、判定できる実装を増やし、同じ基準で複数日の作成・初回合格を記録する必要がある。
